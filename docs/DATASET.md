# PaySim Synthetic Mobile Money Dataset Documentation

## 1. Overview
- **Source**: Kaggle (`ealaxi/paysim1`)
- **Origin**: Generated by the PaySim mobile money financial simulator based on real anonymized transactional logs from an African telecommunications and financial service provider.
- **Scale**: 6,362,620 total transactions across 744 hours (31 simulated days).
- **Fraud Incidence**: 8,213 fraudulent transactions (~0.129% baseline prior). Highly imbalanced.

## 2. Raw Schema

| Column Name | Data Type | Description |
|---|---|---|
| `step` | Integer | Maps 1 hour of real-world elapsed time (1–744). |
| `type` | String | Channel: `PAYMENT`, `TRANSFER`, `CASH_OUT`, `DEBIT`, `CASH_IN`. |
| `amount` | Float | Transaction monetary volume in local currency/USD. |
| `nameOrig` | String | Origin customer account identifier (e.g. `C123456789`). |
| `oldbalanceOrg` | Float | Initial balance of sender account prior to transaction. |
| `newbalanceOrig` | Float | Resulting balance of sender account after transaction. |
| `nameDest` | String | Destination recipient account or merchant identifier (`M...` or `C...`). |
| `oldbalanceDest` | Float | Initial balance of recipient before transaction. |
| `newbalanceDest` | Float | Resulting balance of recipient after transaction. |
| `isFraud` | Integer (0/1) | Ground-truth binary fraud label (illicit siphoning and laundering). |
| `isFlaggedFraud` | Integer (0/1) | Primitive business rule heuristic flagging single transfers &gt; 200,000. |

## 3. Fraud Channel Analysis
Analysis reveals that fraudulent transactions occur **exclusively in TRANSFER and CASH_OUT** channels:
- 4,097 fraud cases in `TRANSFER`
- 4,116 fraud cases in `CASH_OUT`
- 0 fraud cases in `PAYMENT`, `CASH_IN`, and `DEBIT`.

Adversarial pattern: The attacker gains unauthorized control of an account, executes a large `TRANSFER` to a burner destination, and immediately executes a `CASH_OUT` to liquidate the proceeds into untraceable cash.
